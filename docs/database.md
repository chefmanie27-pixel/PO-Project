# Database

Prisma schema: `backend/prisma/schema.prisma`. Prisma 7 CLI configuration: `prisma.config.ts`; runtime uses `@prisma/adapter-pg`. Initial PostgreSQL SQL: `backend/prisma/migrations/202611150001_initial/migration.sql`, followed by integrity checks and owner-membership foreign keys. Run migrations against an empty disposable development database before production use.

| Model                     | Purpose                                                                                         |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| User                      | Firebase UID mapping and profile preferences                                                    |
| Project                   | Workspace, immutable ticket prefix and transactional counter                                    |
| ProjectMembership         | Unique project/user role grant                                                                  |
| Team / Sprint             | Project-scoped delivery context                                                                 |
| Ticket                    | Canonical requirement, UUID, project-unique identifier, owner, rank, version and archive marker |
| TicketDependency          | Directed project-scoped ticket graph                                                            |
| Comment                   | Ticket discussion with author                                                                   |
| Blocker                   | Owner, severity, underlying ticket and resolution                                               |
| Decision / DecisionTicket | Durable decision and many-to-many ticket traceability                                           |
| ReviewItem                | Explicit PO request with category, owner, notes and version                                     |
| AuditEvent                | Actor, entity, action, timestamp and non-secret change history                                  |

UUID IDs are generated by Prisma. Compound project/id foreign keys prevent cross-project team, sprint, ticket hierarchy, dependency and decision links. Owners must have active PO or ADMIN membership, enforced by centralized validation. Indexes cover project workflow, context and activity queries. Membership deletion is not exposed. API graph traversal rejects self-links and dependency/hierarchy cycles under a project lock. Direct SQL writers must preserve these rules; database credentials must remain restricted to the API and trusted migration operators.

`version` is required for ticket, blocker, decision and review updates. A stale version produces HTTP 409. Ticket numbering uses a locked project counter, avoiding `max + 1` races. Reordering locks the project and normalizes rank positions, incrementing versions of affected tickets.

The seed is explicitly opt-in, refuses NODE_ENV=production, and creates only a new DEMO namespace in a transaction. It never updates an existing demonstration project or real records. Bootstrap and migrations are separate from seeding.

Not yet verified here: applying migrations to a running PostgreSQL server, migration replay, seed idempotency against PostgreSQL, and parallel database transactions. Generated schema/client checks alone do not establish these properties.
